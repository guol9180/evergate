# 发版检查清单

> 替代重复的"发布 vX.Y.Z"任务卡：每次发版复制本清单到 DEVELOP_PLAN 一张发版卡并逐项回写证据。版本规则见 [AGENTS.md · 版本与发布规则](../../AGENTS.md#版本与发布规则)。

## 0. 发版前 5 分钟

- [ ] 过一遍 `DEVELOP_PLAN.md` 中全部非 done 卡：blocked 是否有重启条件 / 复查日期；是否有可顺手关闭的 verify 卡
- [ ] 更新 [RISK.md](./RISK.md) 复查日期；确认 `NPM_TOKEN` 未过期（或已启用 Trusted Publishing）
- [ ] 确认本机 `git status` 干净、在 `main`、已 `git pull --rebase`

## 1. 版本号与 CHANGELOG

- [ ] 按 bump 语义判定：修复 → PATCH；新增功能或破坏性变更 → MINOR（0.x）
- [ ] `CHANGELOG.md` 新增精确 `## vX.Y.Z` 段（非空；门禁按此提取 Release 正文）
- [ ] **MINOR 发布先出 `-rc.1`**：tag `vX.Y.0-rc.1` → workflow 以 `next` 通道发布、Release 标记 prerelease → 自用 24h 无回归再打正式 tag

## 2. 本地门禁

- [ ] `gofmt -l .` 无输出；`go vet ./...`
- [ ] `go test -p 1 ./... -count=1`（有 gcc 时加 `-race`）
- [ ] `make coverage-scheduler`（≥90%）、`make coverage-relay`（≥81%）
- [ ] `web/`：`npm run lint`、`npm test`、`npm run build`；`web/dist` 已更新并随提交入库
- [ ] `node --test scripts/*.test.mjs`
- [ ] `make build` 与 `make build-all` 成功
- [ ] actionlint：`go run github.com/rhysd/actionlint/cmd/actionlint@v1.7.7 -shellcheck= .github/workflows/ci.yml .github/workflows/release.yml`

## 3. 发布

- [ ] 提交（`feat:` / `fix:` / `docs:` 前缀）并推送 `main`；等待 `CI` workflow 全绿
- [ ] 打 annotated tag `vX.Y.Z` 指向 `main` 上的提交并推送；等待 `Release` workflow：quality → release → windows-installer → verify-release 全绿（macOS 安装器按开关）
- [ ] Release 资产：`evergate_X.Y.Z_windows_amd64_setup.exe`、`evergate_X.Y.Z_linux_amd64.tar.gz`、`evergate_X.Y.Z_checksums.txt`；无裸二进制、无未签名 DMG
- [ ] npm 五包（主包 + 三平台子包 + `@heguoliang/evergate-updates`）版本 = tag 去掉 `v`，`latest` 指向正式版；npmmirror 可拉取
- [ ] 下载全部资产并按 checksums 重算 SHA-256

## 4. 发布后（必做，不可省略）

- [ ] **真实升级一次**：用上一个正式版安装 → 管理台触发更新 → 经历下载 / 校验 / 安装 / 重启四阶段 → 配置、数据库、自启动选择保留；回写证据（截图或日志行）。这是 T50v 的复验项
- [ ] 全新安装一次：随机初始密码出现在控制台 / 日志；首登强制改密；创建渠道 → 令牌 → 客户端第一次 200
- [ ] 回写 DEVELOP_PLAN 发版卡：Action URL、资产大小与 SHA256、npm dist-tags、升级与首装证据
- [ ] 若任何门禁失败：不要移动 tag；修复后用 `workflow_dispatch` 重放同一 tag

## npm Trusted Publishing 配置（替代 30 天有效的 NPM_TOKEN）

1. npmjs.com → 逐个打开五个包 → Settings → Trusted publisher → GitHub Actions → 填 `owner` / `repo` / workflow 文件名 `release.yml`
2. GitHub 仓库 → Settings → Variables → 新建 `NPM_TRUSTED_PUBLISHING = true`
3. 可删除 `NPM_TOKEN` Secret；workflow 在该变量为 true 时使用 OIDC（`permissions.id-token: write`）并附 `--provenance`
4. 先用一个 `-rc.1` 验证 publish 成功，再用于正式版

## 回滚

发布后发现严重缺陷：按 [回滚与备份](./回滚与备份.md) 恢复升级前数据库备份；重新安装上一版本；用 PATCH 发修复版，不移动或删除已发布 tag。
