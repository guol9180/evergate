# 设计约束：管理台、可观测性与发布

> 从 AGENTS.md 迁出的功能专属实现约束（T73）。改 `web/`、`internal/metrics`、`internal/telemetry`、`internal/selfupdate`、`.github/workflows`、`npm/` 前必读；通用规范见 [AGENTS.md](../../AGENTS.md)。

## 管理台页面与组件（T6 / T32 / T33 / T39 / T76）

- 管理台页面统一使用 `PageHeader`（独立登录/改密页除外），标题与描述字号一致；数据表必须放在 `overflow-x-auto` 容器内并设置合理 min-width，窄屏只允许卡片内横向滚动，禁止页面级横向溢出。
- 现有技术栈里有合理好用的组件就直接用，不手搓同类实现：页面只允许从 `web/src/components/ui.tsx` 取原语（Button / IconButton / Input / Select / Checkbox / Switch / Field / Alert / Dialog / Drawer / ConfirmDialog / SegmentedControl / Progress / Tooltip / Empty / Pagination 等），从 `components/Toaster.tsx` 取 `notify`，图表用 Recharts、图标用 lucide、服务端状态用 TanStack Query；禁止在页面里手写 `<select>` / `<input>` / `<button>` 样式副本。确需新能力时先评估现有依赖，新增依赖按 AGENTS.md 规则在提交说明记录理由。
- 三方无样式原语（T99）：Dialog / Drawer / ConfirmDialog 基于 `@radix-ui/react-dialog`，Select 基于 `@radix-ui/react-select`（`options` 数组 API，空值在内部映射为哨兵），Checkbox 基于 `@radix-ui/react-checkbox`，Tooltip 基于 `@radix-ui/react-tooltip`，Toast 基于 `sonner`；它们只提供行为与无障碍语义，视觉一律映射到语义 token，不得直接使用三方默认配色。
- 分段单选（T102）：SegmentedControl 基于 `@radix-ui/react-radio-group`，保持 `radiogroup / radio` 语义与 roving focus；Radix 在下一拍才移动焦点、再靠「聚焦即点击」选中，keydown / keyup 同帧的快速点按会漏选，因此方向键 keydown 先同步选中，这一段补丁不得删除。下拉选择用 Radix Select 的 ScrollUp / ScrollDownButton 承接长列表，触发器只在 `focus-visible` 与展开态显示品牌色描边。
- 反馈三分法（T99，全站只允许这三种出处）：① 可归因到字段的校验错误 → `Field error`（控件 `aria-invalid` + 红边 + 紧贴其下的图标文字）；② 无法归因的表单 / 弹窗级错误 → `Alert` 置于表单或弹窗正文**顶部**，禁止紧贴提交按钮；③ 保存 / 删除 / 导入 / 导出等瞬时结果 → `notify.*` Toast（右上角、自动消失）。页面级横幅（更新 / 额度预警 / 未配置价格 / 加载失败）放在 `PageHeader` 正下方。`ErrorText` 只用于加载 / 详情类错误。
- 失败反馈唯一出处（T117）：mutation 失败默认由 `lib/mutationCache.ts` 弹一条 Toast；hook 的调用方内联展示错误（`Alert` / `ErrorText`）时，hook 必须声明 `meta.silentError`，同一 hook 服务两种展示面时用参数按调用点决定。禁止在 `mutate` / `useMutation` 的 `onError` / `onSettled` 里调用 `notify.*`（会与全局 Toast 叠成两条），ESLint `no-restricted-syntax` 拦截。
- 表格行内操作优先使用 `IconButton`（自带 `aria-label` + Tooltip），禁止只放一个中文词当按钮；控件说明统一用 `Tooltip`，原生 `title` 只保留给数据截断预览（单元格长文本、上游错误原文）。Drawer 在窄屏必须占满宽度，Dialog 表单栅格在窄屏降为单列。
- 前端图表统一使用 Recharts 共享组件（参照 `web/src/components/TrendChart.tsx`），不得手写 div/SVG 图表；图表宽度 100%，高度必须由响应式规则或 flex 填充，禁止在卡片内留下大块空白；引入图表库需按路由懒加载，避免进入首屏 bundle。
- 前端路由守卫依赖的服务端状态（如 `['me']`）被 mutation 改变时，必须在成功回调同步更新 TanStack Query 缓存；仅重新导航不得依赖旧缓存判断。
- 颜色一律走 `web/src/index.css` 的语义 token（brand / success / warning / danger / info / neutral / surface / line / foreground），禁止在组件里写 Tailwind 调色板类名；状态徽标用 `StatusBadge`，色调只来自 `Tone` 枚举，且永远带文字。
- 危险操作用 `ConfirmDialog` 替代浏览器 `confirm()` / `alert()`；Dialog / Drawer 的 Portal、焦点陷阱、Esc、滚动锁由 Radix 负责，焦点归还由 `ui.tsx` 的 `useRestoreFocus` 捕获打开前的焦点元素（项目没有 `DialogTrigger`，Radix 默认归还目标为空）。对话框关闭按钮不要包 Tooltip：Radix Tooltip 在获得焦点时也会弹出，而对话框打开时焦点正好落在关闭按钮上。
- 前端校验：`npm run lint`、`npm test`（node 单测 + vitest UI）、`npm run build`；`npm run audit:layout` 需本机 Chrome 与运行中的服务，仅本地执行。
- 前端静态门禁（T106）：ESLint 的 `no-explicit-any`、`no-unused-vars`、`react-hooks/exhaustive-deps` 必须开启且零告警（`--max-warnings=0`），TS 必须开启 `noUnusedLocals` / `noUnusedParameters`；依赖漏洞用 `make audit-web`（`npm audit --audit-level=high`）阻断高危及以上。

## 管理台数据写入与会话（T123 / T124 / T137）

- GORM 的 map `Updates` 不经过 `serializer`：含 `serializer:json` 列的表（`channels.models / model_mapping / timeout_config / catalog_diff`、`tokens.allowed_models / allowed_ips`、`model_fallbacks.fallbacks`、`alert_settings.events`）必须用结构体 + `Select(可写列)` 更新（0 / false / nil 也会落库），map 更新只允许标量列；写成裸值会让该行此后无法读出。
- 渠道 / 令牌的表单更新只写可编辑列，不得整行 `Save`：`last_probe_* / status / catalog_diff` 归后台探测所有，整行回写会覆盖并发探测结果。
- 会话是无状态 HMAC Cookie，签名密钥 = 配置 `session_secret` + 落库版本（`schema_meta.session_key_version`）；改密必须在同一事务内轮换版本并在提交后重签当前 Cookie（旧会话跨重启仍失效），版本不进 YAML。会话 Cookie 的 `Secure` 同时看直连 TLS 与 `X-Forwarded-Proto: https`（管理台默认仅本机可访问，代理声明可信）。
- 不存在的下游令牌默认落一条 401 `invalid_token` 请求日志（`log_unknown_tokens` 可关，进程内每分钟最多 30 条），日志永不记录令牌明文。

## 日志（T5 / T57）

- 运行日志（slog JSON 同时写 stdout 与数据目录 `logs/evergate.log`，按大小滚动）与请求日志（入库供管理台查询）分离；GUI 构建无有效 stdout 时不得影响文件日志。

## 可观测性（T26）

- `/metrics` 只允许 loopback 抓取；指标标签只能使用协议、状态码、错误分类、渠道 id、模型名等低基数维度，禁止 key/令牌/请求体/master key；渠道与模型标签必须经过基数上限折叠。
- OTLP 链路导出默认关闭且不得引入 OpenTelemetry SDK（单二进制体积红线）；只支持 OTLP/HTTP JSON，导出失败只告警，不得阻塞或影响请求成功。

## npm 发布与公开 Release（T29 / T30 / T48 / T55）

- npm 发布：主包 `@heguoliang/evergate` 不得包含平台二进制；主包、三个平台子包与 `@heguoliang/evergate-updates` 更新资产包版本必须等于 git tag（去掉 `v`），平台子包先于主包发布，更新资产包在所有公开资产校验完成后发布；`NPM_TOKEN` 仅存 GitHub Secrets，不得写入仓库或日志；token 须为可绕过 2FA 的 Automation/发布专用 token。仓库变量 `NPM_TRUSTED_PUBLISHING=true` 时改用 OIDC Trusted Publishing（`--provenance`），配置步骤见 [发版检查清单](./发版检查清单.md)。
- 公开 Release 只发布版本化安装资产/归档与 checksums，不得重新发布 Windows/macOS 裸二进制；macOS 资产受安装器开关约束。Windows GUI 使用 `windowsgui`、Per-Monitor V2 manifest 与 `internal/winres` 图标资源，console 不得嵌入 GUI 资源。Windows/macOS 必须保持单实例，自启动参数不得自动弹浏览器。

## 一键更新（T30 / T35a / T50 / T54）

- 一键更新优先从 npmmirror → 官方 npm registry 获取 `@heguoliang/evergate-updates` 完整资产包，双源失败才回退 GitHub Release。npm tarball 必须校验 sha512 integrity 与包内 SHA256 checksums；HTTP GET 对连接错误、429、5xx 使用有界短重试。Windows/macOS 必须运行完整安装器，禁止替换 App/程序内单文件；macOS 必须校验 Developer ID 与 notarization。Linux 只从 tar.gz 安全提取唯一 `evergate`，同目录原子替换并保留备份；容器与 npm 安装拒绝应用内更新。

## CI 门禁（T74）

- `ci.yml` 在 main push / PR 运行：前端 lint/test/build 与 `npm audit --audit-level=high`、`go vet`、`make gofmt-check`、`make staticcheck`、`make govulncheck`、`go test -race -p 1 ./...`、`make coverage-scheduler`（≥90%）、`make coverage-relay`（≥81%）、gitleaks、actionlint，macOS runner 编译 darwin cgo 变体。阈值不得高于实测基线；覆盖率报告必须标注为语句覆盖率（T106）。
- 静态分析与漏洞扫描的版本固定在 Makefile（staticcheck v0.8.2、govulncheck v1.10.0），本地与 CI 同口径；`go.mod` 的 `go` 指令跟随已修复标准库漏洞的补丁版本（T106 起为 1.27.4），CI/release 由 `go-version-file` 自动使用同一版本。
