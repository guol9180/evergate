# 运维与配置

本文档记录 EverGate 的配置边界、可观测性、一键更新与运维端点。项目定位与快速开始见 [README](../../README.md)，任务与验收见 [DEVELOP_PLAN](../../DEVELOP_PLAN.md)。

## 配置边界

`evergate.yml` 只负责启动引导：端口、base path、管理 API loopback 限制、SQLite 路径、master key、session secret。首次启动时 `defaults` 与日志保留天数会初始化 SQLite `runtime_settings` 表，此后运行时业务设置以 SQLite 为唯一事实源，管理台「系统设置」保存即热生效：

- 上游连接 / 首 token / 整体超时
- 重试渠道数、每渠道 key 数、重试总时长
- cooldown 失败阈值、基础时长与上限
- 请求日志保留天数、健康探测周期/并发/超时

端口、base path、`server.admin_loopback_only`、SQLite 路径、master key、session secret 修改后需重启。`admin_loopback_only` 默认为 true；设置 false 前应先确认管理端口的网络边界与 TLS。

## 配置与数据路径

Windows 安装器按用户固定安装到 `%LOCALAPPDATA%\Programs\EverGate`，配置与数据共用固定根目录：

- 默认根目录：`%LOCALAPPDATA%\EverGate`
- 配置文件：`<root>\evergate.yml`
- SQLite：`<root>\data\evergate.db`
- 安装器不提供程序、配置或数据目录选择；安装与升级不会覆盖或删除已有配置和数据库

配置发现顺序：

1. 显式 `-config <path>`（相对路径相对 cwd）
2. `EVERGATE_CONFIG`
3. Windows 注册表 `HKCU\Software\EverGate\ConfigPath`
4. 平台默认配置位置
5. exe 同目录 `evergate.yml`（旧便携模式）
6. 当前目录 `evergate.yml`

平台默认位置：

| 平台 | 配置 | 数据 |
|---|---|---|
| Windows | `%LOCALAPPDATA%\EverGate\evergate.yml` | `%LOCALAPPDATA%\EverGate\data` |
| Linux | `$XDG_CONFIG_HOME/evergate/evergate.yml` | `$XDG_DATA_HOME/evergate` |
| macOS | `~/Library/Application Support/EverGate/evergate.yml` | `~/Library/Application Support/EverGate/data` |

配置中的 `storage.sqlite_path` 留空时使用平台数据目录；相对路径相对配置文件目录解析，绝对路径原样使用。标准安装器不迁移旧安装器数据；桌面固定路径如下：

| 平台 | 程序 | 配置与数据根目录 |
|---|---|---|
| Windows | `%LOCALAPPDATA%\Programs\EverGate\evergate.exe` | `%LOCALAPPDATA%\EverGate` |
| macOS | `~/Applications/EverGate.app` | `~/Library/Application Support/EverGate` |

高级用户仍可通过 `-config` 或 `EVERGATE_CONFIG` 覆盖配置位置。启动日志和系统设置页会显示实际配置文件、数据目录与发现来源。

Windows 约定：

```text
HKCU\Software\EverGate
  InstallDir = C:\Users\<user>\AppData\Local\Programs\EverGate
  ConfigPath = <config-dir>\evergate.yml
  DataDir    = <data-dir>
```

卸载默认保留配置与数据；交互卸载会明确询问是否删除，静默卸载始终保留。安装器创建的快捷方式与直接双击 exe 都通过注册表找到同一份配置。

## 桌面运行

- Windows 公开产物只有 `evergate_<version>_windows_amd64_setup.exe`，安装后为无控制台 GUI 与系统托盘
- 托盘菜单提供打开管理台、打开日志目录、重启和退出；日志入口通过 Explorer 定位并选中当前 `evergate.log`
- GUI 使用按数据目录派生的命名互斥（`Local\EverGate-<数据目录哈希>`）保证**同一数据目录**单实例；重复启动不会绑定第二份端口，只打开现有管理台。指向不同数据目录的开发实例可与已安装实例并行
- 安装器可选“登录 Windows 时自动启动”，默认关闭。自动启动使用 `--autostart`，不会因 `open_browser: true` 自动弹出浏览器
- 运行日志同时写 stdout 与 `<data-dir>\logs\evergate.log`，单文件达到 10MB 时轮换并保留 `.1` 备份
- macOS 安装器启用后公开产物为 `evergate_<version>_macos_arm64_setup.dmg`，其中安装器把 App 安装到 `~/Applications/EverGate.app`
- macOS App 为菜单栏应用，不显示 Dock 图标；菜单提供打开管理台、打开日志目录、重启和退出，并通过用户级按数据目录命名的文件锁保持同一数据目录单实例
- macOS 安装器同样可选登录自启与安装完成后立即启动；正式分发包必须完成 Developer ID 签名和 notarization
- macOS 安装器由仓库变量 `ENABLE_MACOS_INSTALLER=true` 和完整签名 Secrets 共同启用；未启用时 Release 不发布未签名 DMG
- Linux 公开产物只有 `evergate_<version>_linux_amd64.tar.gz`，解压后包含 `evergate`、`LICENSE` 与 `README.md`，不创建托盘

Linux、Docker 与 npm 安装版本不创建桌面托盘；CLI 仍按 Ctrl+C 或 SIGTERM 优雅停止。

## 协议接入

同一渠道可声明一种或多种原生上游能力；未声明能力的协议会走 Chat Completions 桥接。

| 下游入口 | 上游路径 | 原生能力开关 | 未声明时 |
|---|---|---|---|
| `POST /v1/chat/completions` | `{base_url}/chat/completions` | 默认支持 | — |
| `POST /v1/responses` | `{base_url}/responses` | 原生支持 Responses API | 转换为 Chat Completions |
| `POST /v1/messages` | `{base_url}/v1/messages` | 原生支持 Anthropic Messages | 转换为 Chat Completions |
| `POST /v1/messages/count_tokens` | `{base_url}/v1/messages/count_tokens` | 原生支持 Anthropic Messages | 返回 400 `messages_native_required` |
| `POST /v1beta/models/{model}:generateContent` | `{base_url}/v1beta/models/{model}:generateContent` | 原生支持 Gemini API | 转换为 Chat Completions |
| `POST /v1beta/models/{model}:streamGenerateContent` | 同上 + `?alt=sse` | 原生支持 Gemini API | 转换为 Chat Completions SSE |
| `POST /v1beta/models/{model}:countTokens` | `{base_url}/v1beta/models/{model}:countTokens` | 原生支持 Gemini API | 返回 400 `gemini_native_required` |

Anthropic Messages 渠道的 Base URL 按厂商填写，网关统一追加 `/v1/messages`：

| 上游 | Base URL |
|---|---|
| Anthropic 官方 | `https://api.anthropic.com` |
| DeepSeek Messages 兼容 | `https://api.deepseek.com/anthropic` |
| Kimi / Moonshot Messages 兼容 | `https://api.moonshot.ai/anthropic` |

- 下游鉴权同时接受 `Authorization: Bearer <token>` 与 `x-api-key: <token>`，兼容 Claude Code 的 `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_API_KEY`
- M→M 透传只改写鉴权、Base URL 与模型映射；`anthropic-version` / `anthropic-beta` 原样转发（未提供版本时补 `2023-06-01`），请求与 SSE 事件不重组
- M→CC 桥接支持文本、`tool_use` / `tool_result`、`tool_choice`、`stop_sequences` 与 usage；`thinking`、`cache_control`、图片/文档块无法等价表达，返回 400 而不是静默丢弃
- Messages SSE 没有 `[DONE]`，以 `message_stop` + EOF 结束；`ping` 事件原样转发，EOF 早于 `message_stop` 视为流中断

Claude Code 接入示例（PowerShell）：

```powershell
$env:ANTHROPIC_BASE_URL = "http://localhost:8787"
$env:ANTHROPIC_AUTH_TOKEN = "eg-你的下游令牌"
claude
```

Claude Code 只自动发现名称含 `claude` 或 `anthropic` 的模型；跨模型路由（例如把 Claude Code 指向非 Claude 模型）属于第三方网关兼容路径，Anthropic 官方不支持，需自行验证客户端行为。

Gemini API 渠道 Base URL 填 `https://generativelanguage.googleapis.com`，网关按 `/v1beta/models/{model}:<method>` 拼接。下游鉴权使用 `x-goog-api-key`（也兼容 Bearer / `x-api-key`），`?key=` query 鉴权会被 400 拒绝，避免 key 进入访问日志。

- G→G 透传保留 `systemInstruction`、`safetySettings`、`tools`、`generationConfig` 与 `functionCall.partial_args`；SSE 为 data-only 帧、无 `[DONE]`，以 EOF 终止
- G→CC 桥接支持文本、`functionCall` / `functionResponse`、工具声明与基础 `generationConfig`；`safetySettings`、`thinkingConfig`、`inlineData`/`fileData`、`topK`、`responseSchema` 无法等价表达，返回 400 而不是静默丢弃
- usage 口径：输入 = `promptTokenCount + toolUsePromptTokenCount`，输出 = `candidatesTokenCount + thoughtsTokenCount`，成本按该口径写入请求日志

Gemini 客户端接入示例：

```bash
curl http://localhost:8787/v1beta/models/gemini-2.5-pro:generateContent \
  -H "x-goog-api-key: eg-你的下游令牌" \
  -H "Content-Type: application/json" \
  -d '{"contents":[{"role":"user","parts":[{"text":"hello"}]}]}'
```

## 健康探测

周期健康探测和管理台「测试连通性」共用同一套协议选择，只请求模型列表，不触发推理：

| 渠道能力 | 探测路径 | 鉴权 |
|---|---|---|
| Anthropic 原生 | `{base_url}/v1/models` | `x-api-key` + `anthropic-version: 2023-06-01` |
| Gemini 原生 | `{base_url}/v1beta/models` | `x-goog-api-key` |
| 仅 OpenAI 兼容 | `{base_url}/models` | `Authorization: Bearer` |

多渠道能力同时声明时按 Anthropic → Gemini → OpenAI 兼容选择。上游返回 404/405 表示列表端点不可判定，渠道标记为 `inconclusive` 并释放 half-open 探测名额；不会因该响应禁用 key。

## 模型目录发现

管理台可以从已保存且至少有一把启用 key 的渠道拉取上游模型目录，用于填写「支持的模型」：

- 只读取模型列表，不调用推理接口，不写请求日志或用量，不改变 key 的 active/cooldown/disabled/half-open 状态
- Anthropic 按 `after_id`、Gemini 按 `pageToken` 翻页，最多 10 页、500 个唯一模型；OpenAI 兼容协议按单页 `data[].id` 读取
- `模型映射` 的方向是“对外模型名 → 上游模型名”。拉取到上游模型后会反查已有映射；多个对外别名可同时成为候选，确认时写入的是对外名
- 候选确认只修改当前渠道表单，不自动保存；令牌的「允许模型」选择器读取启用渠道 `Models` 并集，并显示对应的上游映射提示

## 运维端点

| 端点 | 说明 |
|---|---|
| `GET /healthz` | 存活检查；数据库可达时 200 |
| `GET /metrics` | Prometheus 文本指标，仅 loopback 直连可抓取，非本机 403 |
| `/admin/api/*` | 管理台 API，session 鉴权；与 API 同端口 |

默认端口 `8787`（避开常用 8080），通过 `evergate.yml` 的 `server.port` 修改。

## 可观测性

- `/metrics` 指标包含请求/错误/并发数、首 token 直方图、上游尝试与错误分类，以及抓取时从 SQLite + key 状态机采集的渠道健康与 key 状态
- 指标标签只使用协议、状态码、错误分类、渠道 id、模型名等低基数维度，不包含 key、令牌、请求体或 master key
- 链路导出默认关闭；设置 `OTEL_EXPORTER_OTLP_ENDPOINT`（或 `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`）后启用 OTLP/HTTP JSON 导出
- 支持 `OTEL_EXPORTER_OTLP_HEADERS`、`OTEL_SERVICE_NAME`；显式使用 `grpc` 或 `http/protobuf` 协议会保持关闭并记录告警
- 导出失败只写 warning，不影响请求结果；进程退出时排空队列（最长 10 秒）

## 更新检查

Dashboard 检查新版本时优先读取 npm `dist-tags`（npmmirror → 官方 registry），两源均不可用才回退 GitHub Releases API。完整安装资产从 `@heguoliang/evergate-updates` npm 包获取，GitHub 只作备用；GitHub 可达时补充更新说明链接与资产列表。`EVERGATE_NPM_REGISTRY` 同时收窄版本检查与 npm 更新包链。

## 用量与成本

- OpenAI 兼容 Chat Completions 的流式上游请求会自动设置 `stream_options.include_usage=true`，以取得流结束时的真实输入/输出 token；Responses、Anthropic 与 Gemini 原生流按各自协议读取最终 usage
- 管理台“用量成本”先维护全局默认价或渠道+模型覆盖价（USD / 百万 token）。没有匹配价格时 `cost_status=unpriced`，上游未返回 usage 时为 `no_usage`，旧版本未写状态的历史日志显示为“未记录”
- 请求日志按请求即时展示成本；UTC 日聚合完成后，用量页区分已计价、未计价、无 usage 与历史未记录数量。未知成本显示为 `—`，不会以 `$0` 冒充
- 成本只使用请求完成时的价格快照；修改价格不会追溯重算历史请求，已有 `unpriced` 记录也不会因后来补充价格而改写

## 模型降级

系统设置页的「模型降级」维护源模型 → 有序候选模型链，保存后新请求立即生效：

- 预算阈值：令牌剩余 token 配额低于该值时，跳过源模型直接按链尝试（0 表示不按预算触发）
- 渠道耗尽：源模型先按现有渠道/key 重试预算调度，全部不可用后才进入下一个候选模型
- 令牌可在编辑页关闭「允许模型降级」；候选模型还必须通过该令牌的模型白名单
- 请求日志保留原始模型与实际命中模型，retry_trace 记录降级原因；成本按实际命中模型价格快照计算
- 流式响应一旦已向客户端写出首 chunk，不再因模型降级重试

## 一键更新

管理台 Dashboard 检测到新版本后可直接「立即更新」：

1. 优先从 npmmirror → 官方 npm registry 下载 `@heguoliang/evergate-updates` 的版本化 tarball；两源均失败才回退 GitHub Release
2. npm 通道校验 `dist.integrity`（sha512）与包内 checksums（SHA256）；GitHub 通道校验同版本 checksums
3. Windows/macOS 在 30 秒内优雅退出后排空请求，并打开完整安装器；Linux 安全提取 tar.gz 中的 `evergate` 后同目录原子替换并保留备份
4. Linux 新进程沿用原参数与工作目录；容器环境和 npm 安装版本拒绝应用内更新并提示正确升级方式

约束与行为：

- 下载与校验阶段可取消；进入安装器阶段后退出当前实例，由安装器负责完整 App/程序更新
- `@heguoliang/evergate-updates` 包含完整安装资产而不仅是裸二进制；Windows/Linux/macOS 分别提取 setup、tar.gz 或 DMG，保持安装包级更新
- 安装包缺失、重名、跨版本、SHA256、签名或 notarization 任一门禁失败都不会修改当前安装
- checksums 与安装资产下载对连接错误、429 和 5xx 执行 3 次短重试；404、大小超限和完整性错误不重试
- `EVERGATE_UPDATE_API_URL` 可覆盖 GitHub Release API 地址（镜像/测试）；更新 HTTP 请求沿用进程标准代理环境变量
- npm 四包继续作为独立安装渠道；npm 用户应运行 `npm i -g @heguoliang/evergate@latest`，应用内更新会明确拒绝
- Linux 启动时只保留最近一份 `.bak` 并清理崩溃遗留 `.new-*`；Windows/macOS 完整安装包失败时保留现有程序与数据
- 开发版本（`dev`/`dirty`）、`go run` 临时文件、非标准安装路径或安装目录不可写时拒绝更新并给出原因

## 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `EVERGATE_NPM_REGISTRY` | 未设置（npmmirror → 官方 registry） | 设置后版本检查与 npm 更新包只使用该 registry |
| `EVERGATE_UPDATE_API_URL` | GitHub 官方 release API | 覆盖版本检查 API（镜像/测试） |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | 空（关闭） | OTLP/HTTP JSON traces 端点 |
| `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` | 空 | 优先于通用端点 |
| `OTEL_EXPORTER_OTLP_HEADERS` | 空 | 导出请求头，逗号分隔 `k=v` |
| `OTEL_SERVICE_NAME` | `evergate` | 链路 service.name |
| `EVERGATE_INITIAL_ADMIN_PASSWORD` | 空（随机生成） | 首次启动创建管理员时使用的初始密码；非空时不再随机生成 |

## 初始管理员密码

首次启动若 `admins` 表为空，创建用户名 `admin` 的管理员：

- 未设置 `EVERGATE_INITIAL_ADMIN_PASSWORD`：生成 16 位随机密码（大小写 / 数字 / 符号至少各一），以 WARN 级别同时写入 stdout 与 `logs/evergate.log`（带 `====` 分隔线，仅出现一次）
- 设置了该环境变量：直接使用，日志只记录「使用了环境变量提供的初始密码」而不回显

两种情况都在首次登录强制改密。遗失处理见 [FAQ](./FAQ.md#初始管理员密码在哪里遗失怎么办)。GUI 构建无有效 stdout 时请查看数据目录日志，或使用托盘菜单「打开日志目录」。

## 客户端接入

下游端点与各客户端（OpenAI SDK / Codex / Claude Code / Cline / Cursor / OpenCode / curl）的配置片段见 [README · 接入客户端](../../README.md#接入客户端)。鉴权同时接受 `Authorization: Bearer`、`x-api-key` 与 `x-goog-api-key`；Gemini 禁止 `?key=`。接口契约见 [openapi.yaml](./openapi.yaml)。

## 备份与审计

- 升级前自动备份数据库到 `data/backups/`（保留 5 份），详见 [回滚与备份](./回滚与备份.md)
- 管理台写操作记录在审计日志（`GET /admin/api/audit-logs`，管理台「系统设置 → 审计日志」），不含任何密钥明文
- 配置导出 / 导入：`GET /admin/api/config/export`、`POST /admin/api/config/import`（不含上游 key 与令牌哈希）
