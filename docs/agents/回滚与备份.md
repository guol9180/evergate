# 回滚与备份

## 数据库备份位置

- 升级前自动备份：应用版本变化（非 `dev` / `-dirty` / `-N-g<sha>` 开发态）时，在执行 AutoMigrate **之前**把 `evergate.db` 复制到 `<数据目录>/backups/evergate-<UTC时间>.db`
- 保留策略：按文件名时间戳保留最近 **5** 份，最旧优先删除
- 失败处理：备份失败只记录 WARN 日志，不阻断启动与迁移
- 全新安装（尚无业务表）与开发态版本不会产生备份

数据目录位置：Windows `%LOCALAPPDATA%\EverGate\data\`，macOS `~/Library/Application Support/EverGate/data/`，便携 / Linux 为 `evergate.yml` 同级的 `data/`（详见 [运维配置 · 配置与数据路径](./运维配置.md#配置与数据路径)）。

## 手动备份

### 管理台一键备份（推荐）

「系统设置 → 整库备份」：

- **立即备份**：WAL checkpoint 后复制主库到 `backups/`，与升级前自动备份同目录、同格式，共用保留 5 份的策略；列表展示时间 / 大小 / 库内 `app_version`，可下载、删除
- **上传恢复**：选择备份文件 → 服务端校验（能打开且含 `channels` / `schema_meta` 表）→ **先自动备份当前库**（作为回退点）→ 落盘为 `evergate.db.restore-pending` → 重启生效
- 启动时若存在 `.restore-pending`，会先把当前主库挪到 `evergate.db.pre-restore`，清掉旧 `-wal` / `-shm`，再替换主库；下次恢复会覆盖这份 `.pre-restore`
- 备份中的上游 key 仍是 `master_key` 加密后的密文；恢复到另一台机器需要同一份 `master_key`
- 不打包 `evergate.yml`，不做云端远端存储与定时备份
- 备份 / 恢复操作会写入审计日志（`backup.create` / `backup.delete` / `backup.restore`）

### 手工拷贝

1. 停止 EverGate（托盘菜单「退出」或 `Ctrl+C`）
2. 复制整个数据目录 **与** `evergate.yml`：主密钥在 `evergate.yml`，缺少它备份中的上游 key 无法解密
3. 重新启动

## 回滚应用版本

安装包级更新（Windows 安装器 / Linux tar.gz）不提供自动回滚，按以下步骤：

1. 停止 EverGate
2. 重新安装 / 解压**旧版本**安装包（固定路径安装会保留配置与数据目录，不会覆盖 `evergate.db`）
3. 若旧版本启动报数据库错误（新版本已迁移 schema），用 `backups/` 中升级前的备份覆盖 `data/evergate.db`（同时删除 `evergate.db-wal` 与 `evergate.db-shm`）
4. 启动并核对管理台「运行概览」与「渠道管理」数据完整

## 迁移兼容说明

- 项目处于 0.x 阶段，数据库迁移只用 GORM AutoMigrate：**只增列 / 增表，不删列、不改类型**
- 因此"旧版本读取新版本数据库"通常可用，但不作为承诺；回滚前仍建议还原升级前备份
- `1.0` 之后将按语义化版本承诺配置与 DB 兼容策略（见 AGENTS.md 版本规则）

## 配置级迁移（不含密钥）

管理台「系统设置 → 配置导出 / 导入」：

- 导出：渠道（不含上游 key）、模型降级链、系统设置、价格覆盖、令牌治理字段（不含哈希）
- 导入：按名称幂等 upsert；令牌以**禁用**态导入（无明文 key），需在「令牌管理」重新创建
- 用途：在实例之间搬运渠道与策略，而不是备份数据库

## npm 安装用户

npm 渠道由 `npm i -g @heguoliang/evergate@<version>` 控制版本；应用内更新会明确拒绝（避免绕过包管理器）。回滚即重新安装旧版本。
